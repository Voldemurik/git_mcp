# Подсказки по двум MCP и GigaChat

Это транспортные подсказки, а не готовое решение предметной задачи. Имеющийся код `course/` можно импортировать, но **самостоятельный MCP и цикл агента пишете вы**.

## 1. Собственный MCP

В персональной ветке уже выдан **конкретный сервер** `student/own_server.py`. В нём есть ровно три предметных инструмента с предопределёнными именами и без аргументов, плюс `health_check`. Конкретный контракт — `case/OWN_SERVER_SPEC.md`.

**Транспорт уже работает:** `initialize`, `tools/list`, `tools/call` реализованы на стандартном Python с MCP JSON-RPC через stdio, по образцу успешно проверенного K10 Lite. Он не требует установки MCP SDK для вашего собственного сервера. В `requirements.txt` могут оставаться зависимости для готового Git MCP. Использование SDK/FastMCP по желанию допускается, если сохранены протокольные функции и правила безопасности.

Реализуйте предметную функцию (обычно второй из трёх инструментов): её `TODO` намеренно заканчивается `NotImplementedError`. Первый инструмент уже читает разрешённые CSV/JSON/текстовые файлы, третий записывает структурированный результат в `llm-mcp-result/outputs/`.

Пример для K10:

```python
def read_preprocessing_case() -> dict: ...  # Уже реализовано

def check_tokenizer_config() -> dict: ...  # Самостоятельная реализация

def save_result() -> dict: ...  # Уже реализовано
```

Функция анализа должна вернуть `case_id`, `status`, `sources`, `result`, `checks` и `report_md`. Инструмент `save_result` проверяет этот контракт, сохраняет `result.json` и `report.md` и запрещает запись вне outputs.

Не вызывайте `save_result` из фазы Plan: запрет на запись обязан обеспечивать и хост агентного цикла. При отсутствии предметной реализации никакой фиктивный `completed` не засчитывается.

## 2. Готовый MCP

В `variant.json` указано поле `ready_mcp`, оно же хранится в `case/manifest.json`. В `course.ready.connect_ready(root, ready_mcp)` уже реализованы базовые способы соединения с четырьмя видами готовых серверов. Получите список доступных инструментов вызовом `list_tools()`, затем используйте их через `.call(name, args)`.

| Готовый MCP | Режим | Доступы |
|---|---|---|
| Context7 | Удалённый HTTP | Документация библиотек; при лимитах нужен персональный ключ |
| Filesystem | `npx` / stdio | **Только каталог `case/`, только чтение** |
| Git | `mcp-server-git` / stdio | Восстановленная из `fixture.bundle` временная Git-копия |
| GitVerse | Удалённый HTTP | Только свой репозиторий, API-токен с правами чтения |

Список инструментов каждого MCP может отличаться по версии. Не придумывайте имена: смотрите результат `tools/list`.

## 3. Вызовы GigaChat

Базовый транспорт `course.gigachat_api.GigaChatAPI` и преобразование схем `to_gigachat_functions()` работают с GigaChat API. Это **не агент**: цикл сообщений, выбор инструмента, передача аргументов, исполнение MCP и возврат результата модели реализуете в `student/agent.py`.

Особое внимание: оригинальный `inputSchema` MCP не является гарантированно совместимым со схемой функций GigaChat — используйте адаптер, проверенный на предыдущих лабораторных стендах.


### Понятный маршрут по `student/agent.py`

В **`main()` подключение уже сделано**: `MCPStdio` запускает ваш сервер, `connect_ready` подключает сервер из `variant.json`, а `GigaChatAPI` получает доступ к модели. Менять транспорт ради выполнения практики не требуется.

Дописать нужно три функции: `plan_phase` (только чтение), `build_phase` (предметный MCP и разрешённая запись), `review_phase` (проверка реальных файлов и критическое заключение). Их возвращаемые значения: строка, словарь, строка. `main()` сохранит `plan.md`, `review.md` и служебный `summary.json`, но не напишет предметные результаты за студента.

Минимальная последовательность внутри фазы:

1. Получить списки инструментов через `.list_tools()`, создать непересекающиеся псевдонимы `ready__...`/`own__...`.
2. Отфильтровать инструменты по разрешениям **в коде**, затем вызвать `to_gigachat_functions()`, сохранив отображение имён.
3. Вызвать `gigachat.complete(messages, functions)` и немедленно обработать `gigachat.last_usage` в **собственном** счётчике.
4. Если модель вернула `function_call`, разобрать её `name`/`arguments`, проверить имя и фазу, выполнить соответствующий `.call(...)`, зафиксировать реальный результат в аудите.
5. Вернуть ответ MCP в историю сообщений с ролью `function` и продолжить диалог. Ограничить число шагов и повторных ошибок, иначе CI может зациклиться.

Пример одной записи ответа инструмента в диалоге GigaChat (имя должно соответствовать **объявленной модели функции**, а не исходному имени MCP):

```python
messages.append({"role": "function", "name": public_name,
                 "content": json.dumps(mcp_result, ensure_ascii=False)})
```

Это иллюстрация формата, **не готовый цикл агента**. Самостоятельно реализуйте сообщения модели, маршрутизацию вызовов, контроль прав и аудит. Если вызов делает проверочный код, а не модель, в журнале указывается `actor=host`.

### Статистика запросов — реализовать самостоятельно

`GigaChatAPI.complete(...)` возвращает сообщение модели как раньше. При успешном ответе исходное поле `usage` доступно через `gigachat.last_usage` **до следующего запроса** (при ошибке — `None`). В транспорте нет готового сумматора, отчёта или подсчёта по этапам — **эту часть пишете сами в `student/agent.py`**.

Сохраняйте числа из `usage`, а не расчёт по словам/символам. Считайте запросы отдельно от MCP-вызовов. Поля `prompt_tokens`, `completion_tokens` и `total_tokens` суммируйте по Plan / Build / Review; `precached_prompt_tokens`, если оно есть, фиксируйте отдельно. Если ответ не содержит `usage`, честно отметьте отсутствие информации. Формат обязательного `token_usage.json` указан в `COMMON_TASK.md`.

## 4. Права и аудит

В Plan должны быть доступны только чтения. Build может обращаться к write инструментам своего MCP в пределах `llm-mcp-result/outputs` или создавать предложение патча внутри `outputs/`; не выполняйте прямой push/merge в удалённый GitVerse.

Формат одной строки JSONL:

```json
{"event":"tool_completed","phase":"plan","actor":"model","server":"ready","name":"query-docs","status":"ok"}
```

Различайте `actor=model` и `actor=host`: вызовы хоста не заменяют самостоятельную работу модели. Не записывайте в аудит секреты, токены, полное содержимое приватных файлов и системные промпты.

## 5. Обязательные файлы артефакта

```text
llm-mcp-result/
  manifest.json           # case_id и версия реализации
  summary.json            # backend=gigachat и итоговые статусы
  audit.jsonl             # реальная последовательность MCP-вызовов
  token_usage.json         # подсчёт GigaChat запросов и токенов студентом
  plan.md                 # план агента
  review.md               # проверка результата
  checks.json             # формирует Checker
  outputs/
    result.json           # case_id, status, sources, result, checks
    report.md             # предметный отчёт
    proposal.patch        # для Git-кейсов, если есть исправление
```

Структура общего JSON описана в `COMMON_TASK.md`. Помните: никакие поля `summary` сами по себе не доказывают подлинность аудита. Преподаватель проверяет исходники и историю CI.
