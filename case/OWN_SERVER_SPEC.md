# P04 — обязательные инструменты собственного MCP

Вам выдан файл `student/own_server.py` с тремя **конкретными** инструментами. Не нужно выбирать их названия или придумывать схемы. Все три доступны через `tools/list` и вызываются через `tools/call`.

| Инструмент | Вход | Выход | Что делать студенту |
|---|---|---|---|
| `get_user_data()` | Нет аргументов | `case_id`, `sources`, `data` | Чтение готово: использует фиксированные файлы из `case/` |
| `clean_recommendations()` | Нет аргументов | `case_id`, `status`, `sources`, `result`, `checks`, `report_md` | **Реализовать предметную проверку:** убрать повторы/просмотренные/несуществующие позиции и вычислить Recall@K |
| `save_result()` | Нет аргументов | `status`, `files` | Сохранение готово: пишет только в `llm-mcp-result/outputs/` после проверки ответа предметного инструмента |

## Что положить в предметный результат

Очищенный top-k по user_id и численные значения recall@k.

Источники — относительные имена файлов из `case/`; результаты привязывайте к конкретным ID записей, если они есть. `report_md` — полноценное пояснение решения, а не повтор списка JSON-полей.

## Что уже реализовано

- MCP JSON-RPC stdio: инициализация, список инструментов, их вызов.
- Безопасное чтение только конкретных файлов этого варианта.
- Запрет на произвольную запись и проверка выходного JSON.
- `health_check()` для диагностики (не учитывается как предметный инструмент).

## Чего намеренно нет

- Предметного алгоритма внутри `clean_recommendations()`: его пишет студент.
- Готового GigaChat-агента и реализации Plan/Build/Review.
- Ответов на исходные учебные данные.

**Важно:** не считайте инструмент работающим, пока его обработка не реализована. При вызове `clean_recommendations()` до реализации сервер вернёт ошибку `NotImplementedError`.
