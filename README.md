# SmartClass — GigaChat + MCP, практика по алгоритмам и прикладному ИИ

В этом шаблоне 24 персональных варианта: **12 Context7** (NumPy, pandas, scikit-learn, Hugging Face/CLIP), **6 Git/GitVerse**, **6 Filesystem**.

**Правило курса:** каждый студент реализует предметную логику **одного собственного MCP-сервера** (три заранее заданных инструмента в персональном `student/own_server.py`) и подключает **один готовый**. GigaChat управляет инструментами в одном цикле **Plan → Build → Review**. 

Начните с [START.md](START.md): **ваш репозиторий → ветка `student/<логин>` → дождаться `SmartClass - Create personal MCP task` → прочитать TASK.md → выполнить работу → добавить ключ GigaChat в Secrets → вручную запустить Checker → Pull Request в master**.

Папки `course/` и `.gitverse/workflows/` — инфраструктура. Пишите код в `student/`, входные данные находятся в `case/`, созданный вариант закреплён в `variant.json`. Эти файлы появятся только в вашей рабочей ветке после успешного Create.

Библиотеки и примеры подключения — в [MCP_GUIDE.md](MCP_GUIDE.md). Состав выходного артефакта, требования и [правила оценивания](COMMON_TASK.md#оценивание--до-5-баллов) — в [COMMON_TASK.md](COMMON_TASK.md).

**Дополнительно студент самостоятельно пишет учёт токенов GigaChat:** запросы и токены по этапам Plan/Build/Review, общий итог, `token_usage.json` и короткая интерпретация расхода. Транспорт только предоставляет исходный `usage`, без готового счётчика.

**Оценивание — до 5 баллов:** не пройден полный ручной Checker — работа возвращается на доработку; пройден — преподаватель проверяет артефакт и выставляет балл по содержанию. Зелёный CI не гарантирует максимальную оценку.

## Решение P04 — Voldemurik (Filesystem + собственный MCP + GigaChat)

**Задача:** очистить список рекомендаций от повторов, просмотренных и отсутствующих
в каталоге позиций и пересчитать Recall@K по сохранённой релевантности.

### Архитектура

- **Свой MCP** (`student/own_server.py`, JSON-RPC stdio): `get_user_data()` — чтение
  фиксированных файлов `case/`; `clean_recommendations()` — предметная очистка и
  Recall@K; `save_result()` — запись только в `llm-mcp-result/outputs/` с проверкой
  контракта. Плюс служебный `health_check()`.
- **Готовый MCP:** Filesystem (`npx @modelcontextprotocol/server-filesystem`,
  `--read-only`, только каталог `case/`). Реальные `tools/list` и `tools/call`.
- **Агент** (`student/agent.py`): один цикл Plan → Build → Review поверх GigaChat
  Function Calling. Имена инструментов маршрутизируются через отображение
  «публичное имя GigaChat ↔ внутренний псевдоним own__*/ready__*»; аргументы модели
  передаются в MCP-вызов. Права фаз зашиты в коде хоста: в Plan и Review запись
  запрещена (единственный write-инструмент — `own__save_result`, доступен в Build).
  Каждый вызов пишется в `audit.jsonl` с `actor=model`/`actor=host`.
- **Учёт токенов:** собственный аккумулятор считывает `usage` после каждого ответа
  API по фазам, отдельно хранит `precached_prompt_tokens`, честно считает запросы
  без `usage`; итог — `llm-mcp-result/token_usage.json` и раздел в `review.md`.
- **Надёжность:** ограниченные повторы (2) при 429/5xx/сетевых сбоях с паузами;
  лимиты шагов фазы и подряд идущих ошибок инструментов; очистка устаревших
  outputs перед прогоном, чтобы проверки видели только текущий результат.

### Предметный результат (контрольные данные)

U1: кандидаты A,B,B,X,C → удалены A (`already_seen`), B (`duplicate`),
X (`not_in_catalog`); очищенный top-3 = **[B, C]** (допустимых кандидатов меньше K).
Релевантные непросмотренные: B,D; hits = [B]; **Recall@3 = 0.5**, средний = 0.5.

### Локальные проверки (без ключа GigaChat)

```bash
python -m unittest student.tests.test_solution -v   # 10 тестов, включая полный прогон с FakeGigaChat и двумя MCP
python -m course.checker --mode preflight           # 13/13
```

Полный live-прогон выполняется **только** ручным запуском «SmartClass - MCP Checker»
в GitVerse с секретом `GIGACHAT_CREDENTIALS` (ключ никогда не хранится в файлах).

### Известные ограничения

- Набор данных фиксированный; контрольные host-проверки детерминированы (это разрешено).
- Шаблонные `tests/test_agent_starter.py` после реализации фаз закономерно «красные»
  (они проверяют состояние заглушек); `WorkflowTests` требует `.gitverse/workflows`
  из рабочей ветки GitVerse.Гейт сдачи — ручной Checker, а не эти тесты.
- Отчёт `outputs/report.md` формируется из фактических данных, без зашитых ответов.
