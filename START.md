# Старт: как получить и сдать практику

## Шаг 1. Получите персональное задание

1. В своей версии репозитория создайте **новую ветку от `master`** с именем `student/<ваш_логин>`. Пример: `student/ivan_ivanov`. Для этого можно использовать веб-интерфейс GitVerse, командная строка не обязательна.
2. Откройте вкладку **CI/CD** своего форка и найдите запуск **SmartClass - Create personal MCP task**. Дождитесь завершения.
3. Переключитесь на ветку `student/<ваш_логин>`. В ней появятся `TASK.md`, `variant.json`, каталог `case/` **и персональный `student/own_server.py`**. **В `master` задания не будет.**
4. Прочитайте сначала `TASK.md`, затем `COMMON_TASK.md` и `student/README.md`.

Если `create.yml` не запустился, проверьте, включён ли CI/CD в **настройках вашего форка** и соответствует ли имя ветки формату `student/<логин>`. **Не создавайте вторую ветку для повторной раздачи варианта.** Попросите преподавателя разобраться с первым запуском.

## Шаг 2. Напишите своё решение

В `student/own_server.py` — **персональный MCP-каркас с конкретными тремя функциями**; подробности в `case/OWN_SERVER_SPEC.md`. Реализуйте отмеченную `TODO` предметную проверку. В `student/agent.py` — оркестратор GigaChat. Дополнительные файлы и тесты в `student/` разрешены.

Нужно обеспечить:

- минимум три полезных инструмента **собственного** MCP: читать предметные сведения, вычислять/проверять, сохранять результат с ограничениями;
- реальное подключение **готового MCP**, указанного в вашем варианте, через `tools/list` и `tools/call`;
- реальное использование GigaChat Function Calling (не имитация заранее записанных действий);
- этапы **Plan (только чтение)**, **Build (ограниченная запись)** и **Review (проверка результата)**;
- итоговый JSON, подробный отчёт и журнал фактических действий.

Для Git-вариантов в `case/fixture.bundle` содержится тестовая история коммитов. Её надо восстановить во временную папку; исходный bundle не изменять.

## Шаг 3. Настройте секрет GigaChat

В **своём форке** откройте **Настройки → Секреты/переменные CI/CD**. Добавьте `GIGACHAT_CREDENTIALS` — свой Authorization Key.

Для готового GitVerse MCP также нужен отдельный `MCP_GITVERSE_TOKEN` **с правами только чтения**. Для Context7 при необходимости `CONTEXT7_API_KEY`. Файловый и локальный Git MCP внешнего токена не требуют.

**Никаких ключей в `.env`, исходниках, `TASK.md`, README, коммитах и артефактах.**

## Шаг 4. Запустите одну проверку

Откройте **CI/CD → SmartClass - MCP Checker → Запустить вручную**. Выберите **свою рабочую ветку** `student/<логин>`. Проверка выполнит один цикл агента и сохранит **один артефакт `llm-mcp-result`**.

Скачайте артефакт и посмотрите `checks.json` и `summary.json`. Там будет видно, какой этап не пройден. Исправляйте решение **в той же ветке** и повторно запускайте **только Checker**. Вариант не меняется.

**Ещё одно обязательное действие:** самостоятельно реализуйте учёт токенов запросов GigaChat по этапам. В итоговом артефакте должен быть `token_usage.json`, а в отчёте — короткий вывод о расходе. Готового счётчика в шаблоне нет; подробности в `COMMON_TASK.md` и `MCP_GUIDE.md`.

**Важно:** для допуска к оцениванию требуется успешный **полный ручной Checker** (`checker_mode: "live"`, `status: "passed"`), а не только успешный `preflight` или зелёный PR. Если полный Checker не прошёл, вернитесь к исправлениям.

## Шаг 5. Отправьте работу

После успешного ручного запуска создайте **Pull Request / запрос на слияние из `student/<логин>` в `master` своего форка**. Укажите ссылку на успешный CI и кратко опишите архитектуру, ограничения и результат. Необязательно сливать PR, если преподаватель этого не требует.

При открытии PR может сработать **только предварительная проверка без GigaChat**: она **не заменяет** ручной Checker. Триггеры PR на GitVerse поддерживаются не полностью, поэтому основным подтверждением остаётся ручной запуск.

## Как оценивается работа — до 5 баллов

- **Полный Checker не пройден:** работа возвращается на доработку; предметная оценка пока не выставляется.
- **Полный Checker пройден:** преподаватель проверяет содержимое артефакта и выставляет **до 5 баллов**. Зелёный CI — допуск к оцениванию, а не автоматическая пятёрка.
- Оцениваются предметный результат, подтверждения работы агента и двух MCP, содержательность отчёта, согласованность артефактов и соблюдение ограничений. Причины снижения балла будут описаны в комментарии к оценке.

Подробные правила — в разделе [«Оценивание — до 5 баллов»](COMMON_TASK.md#оценивание--до-5-баллов).

## Если что-то не работает

- Нет `TASK.md` — проверяйте `create.yml` и ветку; не правьте каталог `course/`.
- `GigaChat credentials` — секрет должен быть в **этом** форке.
- `429 Too Many Requests` — временный лимит GigaChat, повторите позднее; не отключайте проверку TLS.
- `tools/list` пустой — посмотрите лог запуска своего MCP и версии зависимостей.
- Запись запрещена в Plan — это ожидаемая политика, не отключайте её.
- CI пишет `preflight_passed_not_submitted` — это **ещё не сдача**.
